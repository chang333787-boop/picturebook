# COMPASS-ROSE-AUDIT — 나침반형/마인드맵형 결과지 확장 조사 (구현 없음)

2026-07-02 · read-only 설계 조사 · 기준 COMPASS-SHEET-1(카드형 설계도) live 이후

## 1. 현 카드형 vs 나침반형
현 SHEET-1 = 시간축 줄거리 + 2열 카드 10(정보 전달 최적·인쇄 안정). 나침반형(D-18)은
"내 이야기의 중심과 방향"이라는 **은유 가치**가 더해지는 형태 — 정보량은 같고 정서/브랜딩 차이.

## 2. 배치 설계(권장안)
- **중앙 = coreMessage(끝까지 지킬 중심)** — "나침반 바늘이 가리키는 것" 은유가 가장 정확.
  (protagonist는 N방위 시작점, trueEnding은 도착점이 자연스러움 — 중앙은 '변하지 않는 것'이어야 함.)
- **4방위(1안)**: N 주인공 → E 목표 → S 어려움 → W 중요한 선택. 테두리 밴드에 시작→사건→진엔딩 시간띠.
- **6방위(2안)**: 주인공/목표/시작/어려움/선택/진엔딩 — 정보 6개는 방위 은유가 흐려짐. **1안 권장**.
- alternatePath는 나침반 밖 점선 화살표("다른 길") — 분기 은유와 일치.
- targetLength·자유메모는 하단 각주.

## 3. 모바일 적합성 — ⚠ 주의
원형 배치는 390px에서 라벨이 겹치거나 축소되어 **카드형보다 가독성이 떨어질 가능성 높음**.
권장: 화면(모바일)은 현 카드형 유지, **나침반형은 인쇄/태블릿 가로 전용 뷰**로 한정.

## 4. 인쇄 활동지 적합성 — 높음
A4 1장 중앙 원형 + 여백에 학생이 손으로 덧쓸 공간 — "쓰기 전 설계지" 방향과 정확히 일치.
빈칸(유예) 방위는 점선 원으로 두어 "만들면서 채우기" 활동 유도 가능.

## 5. 기술 판단
- **SVG 권장**: 원형 배치·방위선·점선 화살표는 CSS(grid/absolute)로도 가능하나 각도·선 연결이
  번거로움. 인라인 SVG(뷰박스 800×800) + `<foreignObject>` 없이 text 요소로 충분 — 라이브러리 0.
- 데이터는 **storyMapV2 그대로 사용 가능**(추가 필드 불요) — buildStoryMapV2가 이미 정본.
- AI 마인드맵 생성 시 필요한 데이터도 동일(storyMapV2 + userNotes) — 서버 부담은 후속 SUMMARY-AI 사안.
- 장식 과잉 위험: 아이콘·색은 현 SHEET 팔레트(sage/cream) 유지, 장식 요소는 방위선+중앙 원까지만.
