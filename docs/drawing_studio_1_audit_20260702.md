## 3. 비교군 기준 (기능군 수준 — 따라 만들 대상 아님)
- **Sketchbook**(기본 스케치 사용감): 펜/지우개/색/굵기/undo-redo/넓은 캔버스 → **가지 현재가 전부 충족**. 레이어·다양한 브러시 엔진은 미충족이나 목표 외.
- **Tayasui Sketches School**(어린이 친화): 도구 수 절제·직관 배치·종이 질감 → 가지가 배울 점은 **"기능 추가"가 아니라 "도구 밀도 절제"**(현재 도구 8+펜4종+투명도+압력은 저학년에게 오히려 많은 편)와 종이 배경(2차).
- **ibisPaint**(기능 다수): 레이어·선택/변형·텍스트·자 → 가지 기준 대부분 **과한 기능**으로 분류. undo/redo·도형은 이미 있음.
- **Procreate**(상한선): 고급 브러시·제스처·타임랩스 → 전부 **제외 기준** 확인용.

## 5. 1차 구현 3안
**A안 · 최소 안정 개선 (★추천)** — viewer-edit.js 소폭·위험 낮음
- ①저장 성공 토스트("그림을 저장했어요") ②저장 중 버튼 busy(disable+"저장 중…")
  ③빈 캔버스 저장 확인("아직 그린 내용이 없어요. 이대로 저장할까요?" — 픽셀 샘플 검사)
- 테스트: 저장 성공/실패/이중클릭/빈캔버스/기존 그림 재저장 · 위험 Low
**B안 · 체감 개선** — ①도구 "간단히 보기" 토글(저학년: 펜/지우개/색/굵기/undo만)
  ②undo 히스토리 메모리 최적화(실측 후: 30×~3MB≈90MB 상한 가능성) · 위험 Medium(도구 상태 로직)
**C안 · 확장** — 종이 배경/배경색·localStorage 임시저장·스티커 · 위험 Medium·필요 근거 아직 약함

## 6. 저장/데이터 안전성 (§6 답)
toDataURL→Storage(고유경로·기존 객체 overwrite 없음)→lock 확정 후에만 imageData 기록→flush 실패 시
신규 객체 cleanup+로컬 복원(기존 그림 보존). 재저장=새 URL(기존 s2는 hash 불일치→stale). 자동 변환 0.
undo 메모리만 관측 필요. **저장 실패 시 기존 그림 보존 확인됨.**

## 7. 위험도
- Critical/High: **0** (그림 손실 경로 없음 — 미저장 경고 3경로·저장 복원 로직 존재)
- Medium: ①저장 이중클릭 중복 업로드 ②undo 히스토리 메모리(~90MB 상한 추정·실측 필요) ③빈 캔버스→imageS2 입력 가능
- Low: 저장 성공 안내 부재·도구 밀도(저학년)·종이 배경 부재
- NOT_VERIFIED: 실기기(iPad) 터치/펜 안정·모달 화면 스크린샷(실 편집 세션 필요라 이번 read-only에선 코드 기준)
