# 직접 그리기 사용성 재감사 (DRAWING-STUDIO-USABILITY-AUDIT)

방법: **실제 모달을 하니스로 렌더**(실 viewer-edit.js+실 CSS)하고 Playwright로 조작·실측·스크린샷.

## 1. 왜 재감사인가 — 직전 감사의 한계
DRAWING-STUDIO-1-AUDIT은 기능 **존재** 기준 70% 도달로 판정했다. 그러나 실사용 피드백("그리기 어렵다")
기준으로 재측정한 결과, **기능 목록 평가가 놓친 구조적 사용성 문제가 실측으로 확인됐다.**
사용자 체감이 옳았다.

## 2. 결정적 실측 수치
| 항목 | 태블릿 가로(1180×820) | 모바일(390×844) |
|---|---|---|
| 도구바 인터랙티브 컨트롤 수 | **35개**(버튼+슬라이더+체크박스) | 동일 |
| 40px 미만 버튼(터치 타깃 미달) | **30/35개** | 27개 |
| 도구바가 다이얼로그에서 차지하는 비율 | 21%(3줄) | **49%** |
| **캔버스 높이** | 439px | **179px** |
- 스크린샷: 모바일에서 화면 절반이 도구, 그림 공간은 하단 손바닥만 한 흰 박스.
- 조작 자체는 짧다: 기본 펜 **0클릭 즉시 그리기 가능**(선 긋기 실측 성공), 색/굵기/지우개 각 1클릭.
  → 문제는 "몇 번 누르나"가 아니라 **"35개 사이에서 찾기·그릴 공간·누를 수 있는 크기"**다.

## 4. Sketchbook/Tayasui 사용감 기준과의 차이
그 앱들의 공통: **캔버스가 화면의 주인**(대부분 90%+), 도구는 가장자리 최소, 고급 기능은 숨김.
가지: **도구가 화면의 주인**(모바일 49%·태블릿 3줄), 8도구+보조 6종이 전부 1급 노출.
→ 차이는 기능 수가 아니라 **위계**: "먼저 그리고, 필요할 때 도구를 꺼낸다"가 뒤집혀 있다.

## 5. 시나리오 평가
- **A(처음 학생)**: 선 긋기는 0클릭 성공. 그러나 첫 화면에서 35개 컨트롤을 마주함 — "어디를 봐야 하지"
  비용이 큼. 교사 설명 필요 항목: 도형채움/투명도/압력/색따기/이동(5개+).
- **B(실수 학생)**: 전체지우기 confirm ✅·닫기 경고 ✅·그림 손실 위험 낮음. 단 되돌리기가 눈에 안 띄어
  "지우개로 다 지우는" 우회 행동 예상.
- **C(태블릿/모바일)**: 태블릿은 사용 가능(캔버스 439px·다만 터치 타깃 30개 미달). **모바일 세로는
  사실상 그리기 부적합**(캔버스 179px) — 현재 최대 문제.

## 8. 다음 구현 재정의 — **옵션 3: SIMPLE-MODE + SAFETY 묶음**
직전 추천(안전장치 3건)만으로는 "그리기 어렵다"가 **해결되지 않는다**(원인 ①②가 그대로).
**DRAWING-STUDIO-2-SIMPLE**: ⓐ간단 모드 기본(핵심 6요소만·고급은 [🧰 도구 더보기] 토글·기존 전체
도구는 그대로 보존 — 삭제 아님·상태 로직 무변경) ⓑ모바일 도구바 압축→캔버스 확대 ⓒ선택 도구
강조+상태 1줄 ⓓSAFETY 3건(성공 토스트·busy·빈 캔버스) 동승. 목업 불요(방향이 명확·기존 UI 재배치).
2차: 터치 타깃 일괄 44px·undo 메모리 실측.

## 9. 위험도/테스트 계획
위험: 도구 로직은 무변경(노출만 제어)이라 낮음 — 회귀 포인트는 "더보기 접힘 상태에서 기존 기능 접근".
테스트: 하니스(이번에 확보한 방식) — 기본 화면 컨트롤 수 ≤12 확인·전 도구 더보기 경유 접근·모바일
캔버스 높이 ≥360px 목표·시나리오 A/B 재실행·기존 저장/경고 회귀.
