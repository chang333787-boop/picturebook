# imageS2 — 모델 평가 계획 (호출 0 · 설계만)

> 단계: BRANCH-IMAGE-S2-PHASE-0. 정본: `가지_AI이미지_PRD_확정.md` 부록 A.
> ⚠️ **이번 단계에서는 실제 모델 호출·결과 이미지 생성을 하지 않는다.** 하니스·표·폴더 구조만.

---

## 1. 후보 / 모델 ID 정책
- 후보군: **Gemini 이미지 편집 계열**(예: Nano Banana 류) vs **OpenAI 이미지 편집 계열**(gpt-image 적정 등급).
- **정확한 최신 모델 ID는 평가 시점에 각 공식 문서를 확인해 확정한다.** 이 문서에 ID를 하드코딩하지 않는다(변동·deprecate 위험).
- 결정은 아래 평가표를 실제 샘플로 채운 뒤(IMAGE-S2-8). 그 전까지 provider 미선택.

## 2. 평가 원칙
- 기능 = **편집(restyle)**: 학생 원본 → 그림책풍. 새 그림 생성 아님.
- 고정 프롬프트(PRD §6): restyle · 내용 보존 · 새 요소 금지 · **배경만 가로 연장**. 입력 압축 장변 1600px. 출력 그림중심형 가로 프레임(3:2 권장, `docs/image_s2_implementation_plan.md` §1).
- 동일 프롬프트·동일 입력으로 후보 간 1:1 비교.

## 3. 샘플 데이터 (개인정보 0)
운영 학생 실데이터 **사용 금지**. 다음만 사용:
- 사용자 제공 테스트 이미지 / 가상 샘플 / 개인정보 없는 테스트 그림.

필수 샘플 세트(PRD 부록 A):
1. 앱 그림판 단순 선화
2. 색칠 그림
3. 인물 2명 이상
4. 배경 없는 그림
5. **한글 말풍선 포함**(필수)
6. 종이 스캔
7. 휴대폰 촬영
8. 세로 그림
9. 정사각 그림
10. **같은 캐릭터 연속 3장면**(장면 간 일관성용)

## 4. 평가표 (샘플마다 1~5점 + 탈락 여부)
각 샘플 × 각 후보에 대해 기록:

| 항목 | 점수(1~5) |
|---|---|
| 원본 캐릭터 수 보존 | |
| 핵심 사물 보존 | |
| 구도 보존 | |
| 위치 관계 보존 | |
| 새 요소 미추가 | |
| 배경 연장 자연스러움 | |
| 그림책풍 품질 | |
| 한글 보존 | |
| 장면 간 인물 일관성 | |
| 처리 시간(초) | (실측) |
| 장당 비용(USD) | (실측) |
| 안전 차단 빈도 | (횟수) |

**배경 연장 자연스러움 기준(구체화)**: 실프레임(3:2/1.414)에서 **원본 콘텐츠 영역 밖(주로 좌우)** 만 하늘·바닥·벽·종이색·숲 질감/패턴 연속으로 확장. 새 인물·동물·건물·차량·핵심사물·길·문·표지판·사건암시·시간대/날씨 변화·중심 피사체 이동/확대/축소 = 0이어야 만점.

## 5. 탈락 조건 (PRD 그대로 — 하나라도 해당 시 제외)
- 캐릭터 수 변경
- 핵심 사물 추가·삭제
- 인물 위치 대폭 변경
- 이야기 의미 변경
- 한글 의미 왜곡
- 부적절 요소 생성

## 6. 결과 폴더 구조 (`docs/image-s2-model-eval/`)
```
docs/image-s2-model-eval/
  README.md          # 사용법·이번 단계 호출 0 명시
  inputs/            # 테스트 입력 이미지(개인정보 0). 현재 비어있음.
  gemini/            # Gemini 후보 출력(평가 시 생성)
  openai/            # OpenAI 후보 출력(평가 시 생성)
  scores.json        # 점수 스키마(템플릿)
  comparison.md      # 후보 비교/최종 결론(템플릿)
```
- `scores.json` 스키마: `{ sample: {id, type}, results: { provider: { modelId, scores{항목:1~5}, timeSec, costUsd, safetyBlocks, disqualified, notes } } }[]`.
- 실제 입력/출력 이미지는 평가 단계(IMAGE-S2-8)에서 추가. **이번 단계에는 이미지 0.**

## 7. 평가 → 결정 흐름
1. 샘플 세트 확정(사용자 제공/가상).
2. 후보별 모델 ID 공식 문서 확인.
3. 고정 프롬프트로 1:1 변환(IMAGE-S2-8에서).
4. `scores.json` 채움 → 탈락 필터 → `comparison.md` 결론.
5. provider 결정 → IMAGE-S2-9에서 stub 교체.
