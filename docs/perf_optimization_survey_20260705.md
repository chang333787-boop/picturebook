## 2. CSS 분석 (저사양 태블릿 보조 요인)

- **backdrop-filter 스택**: 텍스트 모드 본문상자 blur(16px)+선택지 blur(10~14px) 동시(viewer.css:1985·2199·2266).
  단 **WIN-TAB-1 경감(전환 중 blur→3px)이 이미 구현·JS 타이밍 정상 동작 확인**(viewer-render.js:43-49). → 유지.
- **상시 무한 애니메이션**: 선택지 화살표 bounce 1.8s infinite(v03-modes.css:929) — 선택지 떠 있는 내내 GPU 소모. 소폭.
- `transition: all` 4곳 — **전부 편집 UI**(.edit-toggle 등)라 감상 무관. 기각.
- repeating-gradient 스킨(paper-desk 5중첩 등) — 정적 렌더 1회 비용, 애니메이션 결합 없음. 수용.
- CSS 685KB 파싱 — 로드 1회 비용. 마감 단계 분할 리팩터링은 위험>이익. **하지 않음**.

## 3. 권고 레버 (우선순위)

### L1 — IMG-PREFETCH-1: 다음 장면 이미지 사전로드 ★최대 효과·저위험
장면 렌더 완료 후 idle에 **현재 장면 선택지 target들의 이미지**를 `new Image()`로 미리
받아 브라우저 캐시에 적재(표지에선 entry 장면). 클릭 시 그림 즉시 표시(3초→0).
- DB write 0·렌더 경로 무변경·실패해도 기존과 동일(무해). 동시 2~3장 제한.
- 기대: 장면 이동 체감의 가장 큰 덩어리 제거.

### L2 — TRANS-TIME-1: 전환 시간 정책 (UX 결정 필요 — 사용자 승인)
현 곡선: 50%=1.2s·71%=2.17s·100%=3.5s. 초등 감상 반복 클릭에 과함.
- 후보 A(보수): 상한만 캡(예: 최대 1.5s) — 기존 작품 느낌 최대 보존.
- 후보 B(적극): 곡선 전체 완화(기본 0.6~0.8s·최대 1.5s).
- 어느 쪽이든 저장값(sceneTransitionSpeed)은 불변·렌더 해석만 변경.

### L3 — 선택(미세): 화살표 bounce를 3~4회 후 정지(또는 prefers-reduced-motion 존중). 소폭.

### 하지 않음
CSS 분할/삭제 리팩터링 · blur 정책 변경(WIN-TAB-1 충분) · transition:all(감상 무관) ·
이미지 재압축 정책 변경(원본 보존 원칙·서버 리사이즈는 별도 트랙).
