# 인쇄 기능 설계 감사 — 쓰기후 자료 + 그림책 분기 인쇄 (PRINT-1-AUDIT)

2026-07-02 · read-only(코드 무수정·AI 0·DB 0) · main HEAD `3bfdd5e`
**현실 조건(설계 기준)**: 학생=태블릿 제작 · **교사=PC에서 열어 확인·인쇄**. 1차 인쇄 기준 기기 =
**교사 PC(데스크톱 Chrome·A4)**. 태블릿 인쇄는 보조(품질 보장 안 함)·모바일 그림책 인쇄 범위 제외.

## 1. 왜 두 종류로 나누나
| | 쓰기후 자료 인쇄 | 그림책 작품 인쇄 |
|---|---|---|
| 용도 | 고쳐쓰기 활동지(보면서 직접 고침) | 완성작 종이책(감상·전시) |
| 기준 본문 | **원본 장면**(고치는 대상이 원본) | **발행 선택본**(textSelections/imageSelections 반영) |
| 데이터 | aiChecks/*/latest (read-only) | scenes + aiVariants (read-only) |
| 난이도 | 낮음(목록형 1~2장) | 중간(번호 map·그래프·페이지 나눔) |

## 2. 기존 print 구조 (재사용 확정)
- 검증된 gate 패턴 2종 공존: `body.tc-print-sheet`(카드형)·`body.tc-print-rose`(나침반형) —
  버튼 클릭 시에만 클래스 부여→window.print→afterprint+2s 제거. **일반 화면/일반 인쇄 영향 0 검증됨.**
- 새 모드는 동일 패턴으로 클래스만 추가: `body.print-write-after` · `body.print-picturebook`.
  gate별 셀렉터가 독립이라 상호 충돌 없음(§8 Critical 방어). @page 전역 사용 금지 원칙 유지.
- A4 1페이지 수납 공식 확보: 종이 폭 690px = 기본 인쇄 여백 내 무스케일(ROSE-1 검증).

## 3. 쓰기후 자료 인쇄 설계 (WRITE-AFTER-PRINT-1)
**데이터**: `aiChecks/workCheck/latest`·`aiChecks/writeAfterQuestions/latest` — 항목이 **장면별**
(sceneId·message·where)이라 활동지에 "N번 장면 — 고칠 점" 그대로 매핑 가능(read once·write 0).
**포함**: 작품명/팀명·날짜 · 생각 점검 질문 목록 · 작품 검사 장면별 확인점 · 항목마다 ☐ 고쳤어요
체크칸 · 학생 메모 빈 줄 · (장면 번호는 §4 인쇄 번호 map과 동일 기준 사용 — 두 인쇄물 간 번호 일치).
**형태 추천**: 질문+검사를 합친 **"고쳐쓰기 자료" 1장**(수업에서 종이 1장이 관리 쉬움 — 결과가
한쪽만 있으면 있는 쪽만). A4 1~2장(항목 15개+ 시 2장 허용, break-inside 가드).
**버튼 위치**: 작품 마무리 2단계("자료 보며 직접 고치기") 카드 옆 **[🖨 고쳐쓰기 자료 인쇄]** —
결과 없으면 미노출. 학생 화면 = "자료 보기" 중심 유지, 인쇄 버튼은 태블릿에서도 보이되 보조(안내
문구 "종이 자료는 선생님 컴퓨터에서 인쇄하면 깔끔해요" 1줄 검토).

## 4. 그림책 인쇄 — 장면 번호 매김 (핵심 설계)
**그래프 실태**: `buttons[].nextId` 자유 연결 — 순환/도달불능/누락 전부 가능(기존 '이야기 길 점검'
이 이미 검사 — 로직 참조 가능). scene num(내부 id)은 생성 순서라 **인쇄 번호와 분리 필요**.
**후보 비교**: A(화면 배치 순) — 배치는 자유라 이야기 순서와 무관 ✗ / **B(시작 장면 BFS) ★추천**
— 읽는 순서와 근접·안정적·즉석 계산 / C(생성 순) — 중간 삽입 시 뒤죽박죽 ✗ / D(교사 지정) — 과함.
**추천 규칙(B안 상세)**:
- 표지 = 번호 없음("표지") · 시작 장면 = **1번**부터 BFS(버튼 순서대로 자식 방문).
- 행동버튼 = "문을 연다 **→ 3번 장면으로 가세요**" (nextId→인쇄번호 map 변환).
- 엔딩/버튼 없음 = "— 이야기 끝 —" 표지. 순환 = "다시 N번 장면으로 가세요"(허용).
- 누락 next = "(연결되지 않음)" · 도달불능 장면 = 뒤에 "추가 장면" 섹션으로 모음(버리지 않음).
- **번호 map은 저장하지 않고 인쇄 시 즉석 계산**(순수 함수 `buildPrintOrder(scenes)` — Node 테스트 가능).
**본문/그림** = 감상 발행 헬퍼 재사용: `getPublishedBodyDisplay…`(textSelections s2)·
`getPublishedImageDisplaySrc`(imageSelections s2) → **감상본과 인쇄본 자동 일치**(별도 로직 0).

## 5. 그림책 인쇄 레이아웃
**1차 추천 = B+D 절충**: 1페이지 = **장면 2개**(그림 위·글·선택지 이동 안내·우상단 번호 배지)
+ **첫 장에 '이야기 길 지도' 1장**(번호·화살표 간단 목록형 — 분기 이해용·SVG 불요 텍스트 트리).
- 표지는 단독 1페이지(제목 크게). 엔딩 표시 명확. 17장면 기준 ≈ 표지1+지도1+본문9 = **11페이지**.
- 흑백 가독: 배경색 의존 금지·번호는 굵은 테두리 배지·이동 안내는 밑줄. 이미지 max-height 고정
  (브라우저 인쇄 멈춤 방지 — 원본이 Storage jpeg라 안전). C(책자 접기)는 후순위.
- **인쇄 전용 레이아웃**(화면 카드 배치와 독립) — 화면 그대로 출력 아님(§추가조건 5 반영).

## 6. 교사용 인쇄 흐름 (기기 분리)
| 안 | 평가 |
|---|---|
| A. maker에서 팀 선택→인쇄 | maker는 편집 세션 — 인쇄 목적으로 무거움 |
| **B. 교사 PC viewer(감상)에서 인쇄 ★** | 학생 저장분+선택본이 그대로 보임(RTDB 단일 진실) — 감상=인쇄 일치 자동. 접근 쉬움 |
| **C. 작품 마무리 '인쇄용 보기' ★(쓰기후 자료)** | 고쳐쓰기 맥락과 일치 — WRITE-AFTER-PRINT 위치 |
| D. admin 팀별 인쇄 자료 | 후순위(관리 편의 — 1차 불요) |
- **학생 태블릿 저장 → 교사 PC 동일 표시 확인**: scenes/aiVariants가 RTDB 단일 소스 + 발행 캐시가
  진입 시 once 로드라 기기 무관 동일 ✅. 선택본 반영도 동일 헬퍼 ✅.
- **권한**: 그림책 인쇄 버튼은 1차 **maker 인증 세션(from=maker)·교사 중심** 노출(공개 감상
  링크 인쇄는 후순위 — 무단 대량 인쇄/저작권 고려). 쓰기후 자료 인쇄는 제작 세션 내부(작품
  마무리)라 자연 제한.

## 7. 데이터 안전성
DB write **0**(전부 read-only·번호 map 즉석 계산·인쇄 DOM은 오버레이 생성→인쇄→제거) ·
원본 body/imageData 접근은 표시 헬퍼 경유 read뿐 · gate 클래스 상호 배타(한 번에 한 모드).

## 8. 위험도
- Critical 방어: gate 분리로 기존 print 2종/일반 인쇄 불침범 · 번호 map은 단일 함수+Node 테스트로
  "이동 안내 오번호" 차단(최우선 테스트 대상).
- High: 순환/누락 그래프 → §4 규칙으로 전부 표현(깨짐 없음) · 이미지 크기 → max-height 고정.
- Medium: 인쇄량(17장=11p — 지도 생략 옵션 검토)·흑백 가독·태블릿 버튼 어색함(보조 표기).

## 9. 구현 순서 (분리 확정)
1. **WRITE-AFTER-PRINT-1** (위험 낮음·즉시 가치): 고쳐쓰기 자료 1장 인쇄. 수정: viewer-ai.js
   (마무리 2단계 버튼+인쇄 DOM)·CSS gate·버스터. 테스트: 결과 유/무·장면번호 일치·A4 1~2p·
   기존 tc-print 회귀.
2. **PICTUREBOOK-PRINT-1** (중간): `buildPrintOrder` 순수 함수+테스트 → 인쇄 오버레이(표지+지도+
   장면2/페이지) → 발행 헬퍼 연결. 수정: 신규 print builder JS·viewer-render 또는 viewer-edit 진입
   버튼·CSS gate. 테스트: BFS 번호·순환/누락/도달불능·selections 반영·A4 페이지 나눔·17장 페이지 수.
3. PICTUREBOOK-PRINT-POLISH: 지도 시각화 개선·책자형·admin 일괄 — 수업 피드백 후.
