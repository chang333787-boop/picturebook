## 1. 현 구조 요지 (직전 감사 + 추가 확인)

  (좌표는 `_base10PositionFor(n)` 재사용) — **targetLength 연결이 기술적으로 열려 있음**.

### 진엔딩 한 줄기를 잡아주는가? — **못 잡는다**
현 7질문이 커버하는 것: 주인공·목표·장애·갈림길·중심(= 이야기의 **재료**).
못 잡는 것: **시작→사건→고조→선택→진엔딩의 순서 있는 흐름**(= 이야기의 **길**).
- goal("이루고 싶은 것")은 결말 방향이지 진엔딩 장면이 아니다.
- obstacle은 정적인 방해물 1개 — "점점 어려워지는 과정"이 없다.
- branchChoice는 갈림길 존재만 — 두 길의 행선지가 없다.
- 그래서 답 7개를 시간순으로 배열할 수 없고, 설계도로 그려도 **지도가 아니라 재료 목록**이 된다.

1. "내 이야기는 이런 흐름이다"라고 말할 수 있나 → **불가**(흐름 축 질문이 0개)
2. 시작-전개-위기-선택-진엔딩 → **2/5**(선택·결말방향만 부분적)
3. 갈림길 질문으로 분기 설계 충분한가 → **불충분**(두 길 행선지 없음)

5. 보기 연타 시 얕음 → 맞음(선행 감사 §4) — v2에서도 출력층+후속이 방어선
6. 설문지→설계도 전환 가능 → 질문 축을 **시간축**으로 바꾸면 가능(아래 v2)

## 3. 큰줄기 장면 수 질문 (targetLength)

**질문(1번, 맨 앞) 권장안**:
> "진엔딩까지 가는 기본 이야기를 몇 장면 정도로 만들고 싶나요?"
> 안내: "여기서 장면 수는 **진엔딩까지 가는 기본 길**이에요. 나중에 다른 선택지와
> 다른 엔딩을 붙이면 전체 장면 수는 더 늘어날 수 있어요."

- 보기: 짧게(약 8장면) / 보통(약 12장면) / 조금 길게(약 15장면) + **아직 모르겠어요**(=기본 12 가정, 결과지에 "만들면서 정하기" 표기)
- **맨 앞 배치 적절**: 그릇 크기를 먼저 정하면 이후 답(사건·고조)의 스케일이 잡히고,
  교사가 차시 계획과 연동해 안내하기 좋음. 부담 완화는 "아직 모르겠어요" 보기가 담당.
- **8/12/15 적정**: 8 = 현행 BASE10의 일반 장면 수(2~9)와 정확히 일치 → 하위호환 기준점.
  정의 제안: **N = 표지·진엔딩 제외한 이야기 장면 수** → 생성 시 표지+N+엔딩 = N+2 노드
  (8→10=현행 BASE10 그대로, 12→14, 15→17). 20~30은 큰줄기 기준 과다 — 배제 동의.
- **노드 수 오해 방지**: "전체 장면"이라는 말 금지, 항상 "진엔딩까지 가는 기본 길"로 표현.
  결과지에는 한 줄로 이어진 길 그림(○─○─○…─◎진엔딩) 위에 N 표기 — 붙는 분기는 점선.
- **BASE10 연결(후속 구현)**: `_mtbBuildBase10Scenes`의 2~9 루프 상한을 opts.count로 —
  기술적으로 소규모. 이번 루프에서는 설계만.
- AI 후속 대상 아님(보기 선택형·판정 불필요) → followup 카운트에서 제외 가능.

## 4. 진엔딩 기본 스토리라인 질문 평가
후보 5문(시작/사건/고조/선택/진엔딩)은:
- **이해 용이**: "기승전결" 용어 없이 사건 순서로 묻는 방식 — 초등 적합. ✅
- **딱딱함 회피**: "어떤 장면에서 시작하나요?"는 수업 아닌 상상 놀이 톤. ✅
- **분기형 정합**: 한 줄기 먼저 → 분기 나중(§5) 원칙과 일치. ✅
- **기존 중복**: obstacle(G5)은 "고조" 질문과 부분 중복 → v2에서 **통합**(별도 유지 불요).
  branchChoice(G6)는 "중요한 선택"과 동일 → **문구만 승계**.
- **보기3 구조 가능**: 전부 대표 상황 3개로 만들 수 있음(§7). ✅

## 5. 분기 설계 보강
검토 3문 중 채택 판단:
1. "어떤 중요한 선택?" → 채택(7번, G6 승계)
2. "진엔딩으로 이어지는 선택은 어느 쪽?" → **별도 질문 불채택** — 8번(진엔딩)을 답하면
   자동으로 정해지는 정보라 중복 부담. 결과지에서 keyChoice→trueEnding 화살표로 표현.
3. "다른 선택을 하면 어떤 일이?" → 채택(9번, alternatePath)

**"좋은/나쁜 선택" 단순화 방지**: 9번 보기를 실패 일변도로 만들지 않는다 —
다른 엔딩 / 돌아오는 길 / 새로운 사건 3방향으로 열어둠(§7 참고).

## 6. v2 질문안 — A안(10문항) vs B안(12문항)

### A안 · 현실적 10문항 (★ 권장)
| # | 필드 | 질문 | 출처 |
|---|---|---|---|
| 1 | targetLength | 진엔딩까지 가는 기본 이야기를 몇 장면 정도로 만들고 싶나요? | 신규 |
| 2 | protagonist | 누구의 이야기인가요? | G3 유지 |
| 3 | goal | 주인공이 가장 원하는 것은 무엇인가요? | G4 유지 |
| 4 | mainlineStart | 이야기는 어떤 장면에서 시작하나요? | 신규 |
| 5 | incitingEvent | 주인공에게 어떤 일이 생기나요? | 신규 |
| 6 | risingTrouble | 일이 어떻게 점점 어려워지나요? | 신규(G5 흡수) |
| 7 | keyChoice | 주인공은 어떤 중요한 선택을 하나요? | G6 승계 |
| 8 | trueEnding | 진엔딩에서는 어떻게 끝나나요? | 신규 |
| 9 | alternatePath | 다른 선택을 하면 어떤 일이 생기나요? | 신규 |
| 10 | coreMessage | 끝까지 지키고 싶은 이야기의 중심은 무엇인가요? | G7 유지 |

- 1~3 = 재료(누가·무엇을·얼마나), 4~8 = **시간축 한 줄기**, 9 = 분기, 10 = 앵커.
  답을 순서대로 읽으면 그대로 줄거리가 된다 — "설계도" 조건 충족.
- 삭제: audience(G1)·purpose(G2) → **질문에서 빼고 결과지 표지의 한 줄 칸**
  ("누구에게 · 어떤 마음을") 으로 강등. 국어과 흔적은 결과지에 남는다.
- 자유메모는 현행대로 검토 화면 별도 유지(질문 수에 미포함).

### B안 · 확장형 12문항
A안 + audience(2번 앞) + desiredFeeling(3번 뒤). 
- 장점: 국어과 성취기준 완전 정합·현행 7문항 완전 포함.
- 단점: **D-23(7~10분) 초과 확실**(12문항+후속 → 13~16분), 초등 집중력 한계,
  뒤 질문(정작 핵심인 스토리라인)에서 피로 누적.
- **판단: 기본 A안. B안은 PRD 개정 시 "교사 옵션(자세히 모드)" 후보로만 기록.**

### 소요시간·상한 영향 (PRD 개정 포인트)
- D-05: 핵심 7→**10** · 전체 12→**15**(후속 여유 5 유지) — functions `MAX_TOTAL`/`CORE_QUESTION_KEYS` 갱신 필요(구현 루프에서 deploy 사안).
- D-23: 목표 **8~12분, 최대 15분**으로 재설정 필요. targetLength·coreMessage는 보기 선택
  위주라 실 부담은 +2~3분 수준으로 추정.
- 저장 하위호환: **기존 answers 7키 구조 불변**. v2는 `preWriting.version=2` + 신규 키 추가
  (audience/purpose 키는 v1 데이터에만 존재 — 결과지가 있으면 표기, 없으면 생략). 마이그레이션 불요.

## 7. 질문별 보기 설계 (A안 전체)

**1 · targetLength** — §3 참조. placeholder 없음(보기 전용). 모르겠어요 ✅(=12 가정).
**2 · protagonist** — 보기: 사람 / 동물이나 생물 / 사물·로봇·상상 속 존재 (G3 그대로).
  placeholder: "주인공이 누구인지, 어떤 점이 특별한지 써 보세요." 모르겠어요 ✅
**3 · goal** — 보기: 중요한 사람이나 물건을 찾고 싶어요 / 누군가를 돕거나 지키고 싶어요 /
  새로운 곳에 가거나 도전하고 싶어요 (G4 그대로). placeholder: "주인공이 가장 바라는 것을 써 보세요." 모르겠어요 ✅
**4 · mainlineStart** — 보기: 평범한 하루에서 시작해요 / 이상한 일이 벌어지며 시작해요 /
  주인공이 낯선 곳에 가며 시작해요. placeholder: "내 이야기가 시작되는 장면을 써 보세요." 모르겠어요 ✅
**5 · incitingEvent** — 보기: 소중한 것이 사라져요 / 뜻밖의 부탁이나 초대를 받아요 /
  위험하거나 이상한 일이 벌어져요. placeholder: "주인공에게 생기는 일을 써 보세요." 모르겠어요 ✅
**6 · risingTrouble** — 보기: 방해하는 누군가가 나타나요 / 시간이 얼마 남지 않아요 /
  주인공의 두려움이나 약점이 발목을 잡아요 (G5 보기 승계·동적 표현). placeholder: "일이 점점 어려워지는 과정을 써 보세요." 모르겠어요 ✅
**7 · keyChoice** — 보기: 혼자 해결할지 도움을 요청할지 / 위험을 감수할지 안전한 길을 고를지 /
  솔직하게 말할지 숨길지 (G6 승계+사용자 후보 반영). placeholder: "주인공이 고민하는 순간을 써 보세요." 모르겠어요 ✅
**8 · trueEnding** — 보기: 주인공이 원하는 것을 이루어요 / 주인공이 중요한 것을 깨달아요 /
  모두가 달라진 모습으로 끝나요. placeholder: "진엔딩에서 어떤 일이 일어나는지 써 보세요." 모르겠어요 ✅(단 유예 시 결과지에 "만들면서 정하기" 크게 표시 — 진엔딩만은 후속 1회 권장)
**9 · alternatePath** — 보기: **다른 엔딩으로 이어져요 / 돌아서 다시 큰길로 돌아와요 /
  새로운 사건이 벌어져요** (실패 일변도 회피). placeholder: "다른 선택을 하면 생기는 일을 써 보세요." 모르겠어요 ✅
**10 · coreMessage** — 보기: 주인공의 성격이나 마음 / 꼭 넣고 싶은 장면이나 대사 /
  결말의 의미나 이야기 분위기 (G7 그대로). placeholder: "끝까지 지키고 싶은 것을 써 보세요." 모르겠어요 ✅

AI 후속 우선순위(followup QUESTION_BRIEF 갱신안): trueEnding·keyChoice·incitingEvent가
구체화 가치 최상 — AI 실패 fallback 고정 후속도 이 3개에 배치(현 G3/G4 방식 승계).

## 8. 결과지/마인드맵 파생 구조 — storyMapV2
```js
writingGuide/compassSummaryV2 = {
  version: 2, generatedAt, source: 'template' | 'ai',       // D-15: 실패 시 template
  targetLength: '8' | '12' | '15' | 'unknown',
  // ── 재료
  protagonist: '', goal: '', coreMessage: '',
  // ── 큰줄기(시간축 — 이 순서가 곧 줄거리)
  mainline: {
    start: '',            // mainlineStart
    incitingEvent: '',
    risingTrouble: '',
    keyChoice: '',
    trueEnding: '',
  },
  // ── 분기(점선 — 큰길에 붙는 것)
  branches: [ { fromChoice: '', result: '', kind: 'altEnding'|'return'|'newEvent' } ],  // alternatePath
  // ── 결과지 표지 칸(질문 아님 — v1 answers에 있으면 채움)
  audience: '', desiredFeeling: '',
  memo: '',                                                  // userNotes 복사 아님·참조
  summaryText: '',                                           // 설계도 문장(템플릿/AI)
  deferredKeys: [],                                          // "만들면서 정하기" 칸
}
```
- **원본 불변**(D-16): preWriting.answers는 손대지 않고 파생 노드만 생성.
- 인쇄 결과지 레이아웃 = 이 구조의 뷰: 상단 표지칸(누구에게·어떤 마음) → 한 줄 길 그림
  (start→…→trueEnding ◎, N장면) → 점선 분기(alternatePath) → 하단 지킬 중심 + 메모.
- 마인드맵 = 같은 데이터의 방사형 뷰(중앙 protagonist·goal).
