# 글자 스타일 재설계 고찰 (TEXT-STYLE-REDESIGN, 2026-07-10)

사용자 문제의식: ①한 장면 안 부분 스타일(일부만 크게/다른 색)이 왜 불가한가 ②본문 선택이 장면꾸미기를 열면 사라짐 ③장면별 통일 대신 "마지막 설정이 다음 장면·엔딩으로 이어지는" 상속.
조사 방법: 워크플로 10에이전트 — 해부 4방향(데이터모델·편집UX·소비자 25+곳·상속전례) → 독립 설계 3안 → 심판 채점 → 적대 비평 2렌즈(둘 다 ship-with-fixes).

## 1. 왜 지금 구조밖에 안 되나 (구조적 원인)

본문(scene.body)은 항상 순수 문자열이고 렌더는 escHtml 후 장면 루트에 CSS 변수만 흘림 — run/span 모델이 아예 없어 ①'한 장면 안 부분 스타일'은 데이터 모델상 불가(장면 단위가 구조적 한계). 저장은 scenes/{num}/textStyle(+필드별 marker textStyleOverride, textTheme/textThemeOverride)이며 텍스트 모드만 작품 기본값 viewer-meta/textDefaults(weight 제외)가 있음. resolver(텍스트 전용, 항목별 독립): ①marker된 장면 예외 → ②작품 기본값 → ③marker 없는 레거시 장면값 → ④floor(일반=null/18/''/normal, 엔딩=jua/20/''/bold). 그림책·무비는 scene.textStyle full 객체 그대로(작품 레이어 없음). '모든 장면에 적용'은 첫 일반 장면에서 1회 복사 push: resolved 스타일+테마를 표지 제외 전 장면(텍스트·그림책은 엔딩 포함, 무비·체험 엔딩 제외)에 덮어쓰고 전 필드 marker=true로 찍음 → 기존 장면 예외를 덮고, 이후 작품 기본값 변경도 안 먹으며, 새 장면엔 미적용(힌트 문구로 명시). 표지=coverTheme 별개 체계, 선택지 라벨=개별 스타일 저장 없음(presentation.placement뿐, 테마 CSS 파생+카드 폰트 상속). pb 글상자는 장면당 1개(x/y/width/height/backdropOpacity) — 상자별 '배경막 진하기' 전례는 있으나 텍스트 부분 스타일 전례는 아님. P4-D variant 스타일은 aiVariants/text/{sid}/{s1|s2}/style/textStyle에 서버 callable로만 기록(원본 불변), variant 보기 중 편집은 fontSize 단 1필드만 허용, 서버 sanitize=폰트 18종 allowlist·10~50 clamp·hex색만. 부수 발견: 텍스트 크기 슬라이더 UI는 12~50인데 로드시 clamp가 10~36이라 37~50 저장값은 재로드 후 36으로 줄어드는 불일치 존재. ③'마지막 설정 상속'은 현 모델(계층 resolution+의도 marker)에 시간축이 없어서, 장면 생성 시 snapshot 복사 또는 resolver 체인 확장이 필요한 별개 설계임.

### 선택이 사라지는 진짜 이유

본문 편집의 정본은 viewer 다듬기 모드의 contenteditable(data-pb-editable="body")이고, maker는 카드 textarea, 모바일도 textarea/input — 스타일 UI(🎨 팝오버)는 viewer 경로에만 존재.
선택이 사라지는 메커니즘 = 재렌더가 아니라 "포커스 이동": 🎨 버튼·팝오버 컨트롤 어디에도 mousedown preventDefault가 없어 클릭 순간 contenteditable이 blur(저장 flush)되며 브라우저 기본 동작으로 선택 표시가 소멸. 팝오버 열기 자체는 frame을 재렌더하지 않음.
판정: mousedown preventDefault만으로는 불가 — 팝오버 핵심 컨트롤이 select(폰트)·range(크기)·color(자유색)라 포커스를 반드시 가져가고, 모든 스타일 쓰기가 `if(!_patchTextStyle()) _scheduleViewerFrameReRender()` 폴백(stage innerHTML 통째 교체)을 가져 live Range가 무효화될 수 있음 → "열 때 Range 저장(문자 오프셋 기반) → 적용 시 복원" 구조가 필요. preventDefault는 색칩/굵기 등 버튼형에만 보조로 유효.
기존 selection 코드는 2곳뿐(선택지 라벨 절단 후 캐럿 복원, 퀵에딧 textarea setSelectionRange). selectionchange 리스너·플로팅 툴바 전례는 0. 다만 "포커스 유지"를 설계 목표로 명시한 주석과 pointerdown preventDefault(글상자 드래그 핸들) 전례는 있음.
_patchTextStyle/_patchPbStyle은 .scene-screen의 CSS 변수만 갱신(DOM 무변경) — 패치 성공 경로에선 커서/선택이 살아남을 수 있는 구조.
①의 근본 원인: textStyle이 장면당 1객체 + 화면 레벨 CSS 변수 + 본문은 순수 문자열(렌더 escHtml, 저장 시 _extractEditableText가 모든 마크업 제거) — 3중으로 부분 스타일이 불가능한 모델.
③: 텍스트 모드는 이미 '작품 기본값 + 장면 sparse override(의도 marker)' 상속 체계가 있고, 그림책은 1회성 "모든 장면에 복사"뿐(신규 장면 자동 적용 없음 명시) — "직전 장면 상속"은 현재 어느 모드에도 없음.

### 본문 소비자 제약(리치텍스트가 불가한 이유)

본문(scene.body)을 읽는 소비자 25+곳 전수 결과: 전부 "순수 문자열" 전제 — escHtml→innerHTML 렌더 12곳, textContent 기반 타자기, textarea 4종 편집기, AI 프롬프트 원문 삽입, byte-hash 3종(작품검사 캐시·s2 stale·race 비교), 글자수 4종(80/300/400/500).
(a) 리치텍스트(HTML in body)는 전면 불가: escHtml이 태그를 글자로 노출, textarea 편집기에서 원시 태그 재저장 오염, AI 프롬프트/safety 정규식/LEN_RATIO/글자수 전부 왜곡.
(b) 별도 styleRuns 오버레이는 모든 읽기 소비자에 안전(무시하면 그대로 동작) — 단 4개 관문: ①viewer adaptScenes가 미지 필드를 버림(명시 매핑 필수) ②saveSceneText ALLOWED allowlist 등록 필수 ③maker 저장이 장면 노드 통째 write(메모리에 실려야 보존; aiVariants식 별도 노드가 더 안전) ④타자기가 innerHTML을 비우고 글자 span 재조립 — 렌더에 runs 적용 로직을 별도로 넣어야 하고 인쇄(textContent)도 미적용이면 화면-인쇄 불일치.
오프셋 파괴: 편집 경로 6곳 전부 body 통째 교체(문자 diff 불가) — maker 카드/미니모달/모바일/루트패널은 <textarea>, 다듬기 contenteditable은 추출 시 스타일 평탄화+브라우저 br/div 정규화로 무변경 저장도 문자열이 달라질 수 있음. AI 직접고침은 AI 문장으로 통째 교체.
따라서 스타일-전용 변경이 body 바이트를 1도 안 건드리는 구조(별도 노드)가 필수 — body가 바뀌면 s2 stale/race skip이 발동하는 게 현 설계의 의도라 오히려 정합.
결론: body 순수 문자열 유지 + styleRuns 별도 노드 + "본문을 고치면 부분 스타일은 초기화(또는 편집면을 run-aware로)" 정책이 유일한 안전 경로. 상속(③)은 body와 무관 — 기존 textDefaults/override resolver(REFINE-IA-2) 확장으로 가능.
선택 유지(②)는 장면꾸미기 열기 시 재렌더(stage.innerHTML 교체)가 selection을 파괴하는 구조 — 열기 전 selection 오프셋 캡처가 선행 조건.

### 상속은 이미 절반 구현돼 있음

① 부분 스타일 불가는 구조적: body가 처음부터 끝까지 순수 문자열(저장·escHtml 렌더·AI·인쇄)이고 스타일은 장면 컨테이너 CSS 변수라 span/range 개념 자체가 없음.
② 선택 소실도 같은 이유 + 팝오버 포커스 이동·stage innerHTML 통째 재렌더 때문. 선택 기반 적용은 리치텍스트 모델 도입 없이는 불가(AI 순수문자열·원본보존 전제와 충돌).
③ 사용자가 원하는 '이어짐'은 텍스트 모드에 한해 절반 이상 구현됨: REFINE-IA-2 resolver가 "marker 예외 → 작품 기본값 → 레거시 장면값 → floor" 동적 체인이고, 신규 장면은 모든 생성 경로(desktop addScene·모바일 BASE10)에서 textStyle 빈 채 생성 → 작품 기본값을 자동으로 따라감('이야기 전체' 탭 문구도 "새 장면에도 같이 적용").
빠진 것: "장면2에서 마지막 설정한 값"이 기본값을 갱신하지 않음 — '이 장면만' 편집은 marker 있는 장면 예외로만 저장됨.
설계 선택지 판정: (a) 생성 시 복사=분기 캔버스라 '직전 장면' 모호+marker 여부 딜레마(정적 복사가 동적 체인과 충돌), (b) 이전 장면 체인=DAG 다중 부모·BFS 필요·상류 수정이 하류를 몰래 바꿈, (c) 기본값 갱신형=인프라 이미 존재(saveProjectTextDefaults)·최소 변경이지만 '모든 장면 적용'이 전 장면에 marker를 박아 놓은 작품은 안 따라오고, 기본값 첫 저장 시 marker 없는 레거시 장면들이 일괄 변함.
모드 격차 큼: 그림책=장면별 full textStyle+복사 버튼(기본값 레이어 없음, saveProjectTextDefaults가 text 전용 가드), 무비=본문 textStyle 렌더 자체가 없음, 표지=coverTheme 별도 체계 → 상속 설계는 텍스트 모드 우선, 그림책은 렌더러가 이미 getTextStyle을 쓰므로 확장 가능, 무비는 대상 없음.
권장 방향: (c)를 텍스트 모드에서 UX만 조정(예: 장면 편집 시 "전체 기본으로 할까요?" 승격 버튼) — DB 마이그레이션 0, resolver 무수정.

## 2. 설계안 3개 요약과 채점

### 설계 1: 형광펜 줄 꾸미기 + 기본값 승격 상속 (LINE-MARK & STYLE-PROMOTE)
**핵심**: body는 끝까지 순수 문자열로 유지하고, 부분 스타일은 "줄(엔터로 나뉜 문단) 단위 형광펜"으로 타협한다. 스타일 표시는 scenes 밖 별도 노드(viewer-meta/textMarks)에 줄 인덱스+줄 텍스트 해시로 저장하고, 렌더 시 해시가 일치하는 줄에만 적용한다(불일치=그 줄만 조용히 해제되는 자가 무효화 — 본문을 고치면 꾸밈이 풀리는 정책이 코드로 강제됨). ②선택 유지는 DOM Range 보존을 포기하고 "줄 탭 선택 상태 모델"로 대체 — 선택이 앱 상태(줄 인덱스)라 blur·stage innerHTML 재렌더에도 생존하며, 태블릿 초등생에게 드래그보다 자연스럽다. ③상속은 새 메커니즘을 만들지 않고 기존 REFINE-IA-2 4단 resolver(viewer-data.js:1410-1447)를 그대로 활용 — '이 장면만' 편집 직후 1탭 "이야기 전체에 적용" 승격 버튼으로 viewer-meta/textDefaults를 갱신하면 marker 없는 장면·엔딩·새 장면이 전부 동적으로 따라온다(자동 승격은 다른 장면을 몰래 바꾸므로 금지). 세 문제 모두 body 바이트 0 변경으로 해결되어 AI·인쇄·원본보존 전제가 구조적으로 지켜진다.

### 설계 2: GLYPH-RUNS + STYLE-FLOW — 본문 하이라이트 오버레이 + 기본값 승격 상속
**핵심**: body는 영원히 순수 문자열로 유지하고, 부분 스타일은 별도 오버레이 노드(문자 오프셋 run 배열)로 저장하는 정공법. 핵심 장치는 run 묶음에 동봉하는 bodyLen+bodyHash 유효성 스탬프다 — 본문이 어느 표면(maker textarea·모바일·AI 직접고침·이야기길)에서든 통째 교체되면 렌더 시 hash 불일치로 runs가 자동 실효(무시)된다. 즉 6개 통교체 편집 경로를 단 1줄도 수정하지 않고 "본문을 고치면 부분 강조는 초기화"라는 초등생도 이해 가능한 정책으로 오프셋 파괴 문제를 흡수한다(fail-safe 방향이 본문 무손상이라 원본 보존과 정합). ② 선택 UX는 장면꾸미기 팝오버(select/range/color가 포커스를 반드시 탈취)를 고치는 대신 역할을 분리한다: 장면 전체 스타일=기존 팝오버, 부분 강조=드래그 선택 위에 뜨는 플로팅 미니 툴바(버튼형 컨트롤만 구성·전 버튼 pointerdown preventDefault로 blur 원천 차단·전례=viewer-edit.js:1933 글상자 핸들). ③ 상속은 REFINE-IA-2 resolver(marker 예외→작품 기본값→레거시→floor)를 무수정 유지하고, '이 장면만' 스타일 변경 직후 "다음 장면들에도 계속 쓰기" 승격 칩으로 saveProjectTextDefaults를 갱신하는 (c)안 — 인프라가 이미 있어 최소 변경이며 새 장면·엔딩까지 동적으로 따라간다.

**데이터**: 저장 위치: {base}/viewer-meta/textRuns/{sceneNum} (신규 키). scenes/{num} 하위가 아닌 이유: maker firebase.js:1102-1124가 장면 노드를 통째 write하므로 다른 클라이언트가 쓴 runs를 에코 전에 덮을 수 있음 — viewer-meta는 maker가 아예 안 건드리고, saveProjectTextDefaults 전례(viewer-data.js:514-536)처럼 필드 단위 .update라 형제 키 안전, database.rules.json 수정 0(viewer-meta 기존 규칙 상속). 스키마: { v:1, bodyLen:N, bodyHash:h(경량 djb2 등), runs:[{s,e,em?,c?}] }. em='big'|'huge'(상대 배율 1.3/1.6em — 장면 fontSize를 나중에 바꿔도 비례 유지, px 절대값 금지), c='red'|'blue'|'green'|'orange'|'purple' 팔레트 토큰(hex 아님 — 테마별 CSS 클래스 .run-c-red로 매핑해 dark/retro 테마에서 대비 자동 보정). 제약: run 최대 12개/장면·겹침 시 병합/분할 정규화·s<e·bodyLen 초과분 절단. 읽기: 렌더 직전 validate(bodyLen 일치+hash 일치) 실패 시 전체 무시. 쓰기: 다듬기 미니 툴바에서만, debounce 후 .ref(viewer-meta/textRuns/{num}).set(). scene.body·textStyle·textStyleOverride·textDefaults 기존 체계는 0바이트 불변. AI variant 보기 중엔 표시 body가 원본과 달라 hash 불일치→runs 자동 미적용(AI 문장에 원본 강조가 잘못 붙는 사고 원천 차단).

**편집UX**: 동선: 다듬기 모드 text-card__body(contenteditable)에서 드래그 선택 → selectionchange 리스너(신설·전례 0이나 표준 API)가 비축소 선택을 감지 → 선택 rect 위에 fixed 미니 툴바 표시. 툴바 구성(전부 button type=button + pointerdown preventDefault → contenteditable blur 없음·선택 하이라이트 생존): [크게] [아주 크게] 토글 2단 + 색칩 5개 + [원래대로] + 장면당 [강조 모두 지우기]. select/range/color input을 배제했으므로 Range 저장→복원의 최난관(포커스 탈취 위젯)이 설계상 소멸. 오프셋 캡처: 선택 Range를 TreeWalker로 걸어 _extractEditableText(viewer-edit.js:1642-1654)와 동일한 br/div→\n 규칙으로 문자 오프셋 {start,end} 산출(마지막 유효 선택을 항상 보관 — 벨트+서스펜더). 적용: runs 배열 갱신 → stage 통재렌더(_scheduleViewerFrameReRender) 금지, 본문 요소 1개만 run-aware HTML로 재조립 → 저장한 문자 오프셋으로 selection 재탐색 복원(전례: viewer-edit.js:1799-1804 캐럿 복원). 다듬기 중 타이핑 시엔 prefix/suffix 공통부 diff로 runs 오프셋을 이동시키고 blur flush 때 새 hash와 함께 재저장(이것까지가 P1 — 안 하면 타이핑 한 글자에 강조가 다 사라져 학생이 당황). 초등 가드: 팔레트·2단 크기만 허용(무지개 본문 방지), 강조 글자수 상한(예: 장면의 50%) 초과 시 안내, [강조 모두 지우기]로 원클릭 복구, 강조는 undo 스냅샷(state.js getSceneText)과 무관한 오버레이라 본문 undo와 충돌 없음. 기존 장면꾸미기 팝오버는 무수정 — 다만 트리거·버튼형 컨트롤에 pointerdown preventDefault를 보조 적용해 캐럿 유지 개선(선택 유지가 더는 팝오버 요구사항이 아니게 됨).

**소비자**: AI(텍스트1/2·작품검사·생각점검): _buildWorkSnapshot(viewer-ai.js:3527)에 runs를 싣지 않음 → 프롬프트는 지금과 byte 동일, functions/prompts.js:625·679 원문 삽입·_scanSafety 정규식·LEN_RATIO·작품검사 캐시해시(functions/index.js:186)·s2 stale/race byte비교(viewer-ai.js:4708) 전부 무영향. AI 직접고침이 body를 교체하면 hash 실효로 강조 자동 소멸(원하면 _applySelected에 runs 노드 삭제 1줄 추가 — 없어도 동작 동일). 감상 렌더: 공용 helper renderBodyWithRuns(body,runs)를 신설해 escHtml 삽입점을 교체 — P1은 텍스트형 본문(viewer-render.js:621)만, 이후 엔딩(1707)·pb(795·871) 확장. runs 무효/부재 시 현행 escHtml 경로와 출력 동일. 타자기(viewer-render.js:3101-3167): per-char span 재조립 시 글자 인덱스로 run 클래스를 tw-char에 부여(글자수 게이트는 textContent 기반이라 무영향). 인쇄: picturebook-print.js:312 등 plain 삽입부에 같은 helper 재사용해 화면-인쇄 일치(P3 전까지는 "인쇄에는 강조 미표시" 한계를 인지하고 P3에서 해소). maker 카드 textarea·미니모달·모바일 textarea: 무수정 — plain 본문만 보이고(정상), 수정하면 강조가 실효되는 정책 그대로. adaptScenes는 건드릴 필요 없음(runs가 scenes 밖이므로) — 대신 viewer-meta 로드부에 textRuns 매핑 1곳 추가. export/import(ui.js:586-638): scenes만 다루면 runs 미포함 — "내보내기에 강조 미포함"을 명시하거나 viewer-meta 동봉(P3 결정).

**상속**: (c) 기본값 승격형 채택 — resolver·저장 경로 무수정. 동작: 장면꾸미기 '이 장면만' 탭에서 폰트/크기/색 변경(_writeStyle 경유) 직후 팝오버 하단에 1줄 칩 "이 글자 모양, 다음 장면들에도 계속 쓸까요? [계속 쓰기] [이 장면만]". [계속 쓰기]=saveProjectTextDefaults(해당 필드)+현 장면 marker 삭제(기본값 추종으로 환원) → marker 없는 전 장면+새 장면+텍스트 엔딩(같은 resolver, viewer-render.js:2035-2056)이 동적으로 따라감. weight는 textDefaults 범위 밖(viewer-data.js:1332 설계 의도)이므로 승격 대상에서 제외 명시(엔딩 bold floor 보존). '모든 장면에 적용' 이력 작품(전 장면 marker 오염) 대응: 승격 시 "다른 장면의 값이 지금 기본값과 똑같으면" marker만 걷어내는 값동등 클리어(학생이 일부러 다르게 한 진짜 예외는 값이 달라 보존됨). 아울러 glyphapplyall(viewer-edit.js:2798-2876) 자체를 textDefaults 1회 write+값동등 marker 클리어로 재구현 — 모바일 _mtbApplyThemeToAll(mobileTextBranch.js:1799-1812)이 이미 같은 방식으로 전환한 전례가 있어 정합적이고, 향후 marker 오염을 끊으며 "새 장면 미적용" 힌트 문구도 삭제 가능. 부분 강조(runs)는 장면 소유 오버레이라 상속 대상 아님(강조까지 다음 장면에 번지면 초등생 혼란 — 의도적 배제). 모드 판단: 텍스트 모드 1차. 그림책 말풍선=runs 이식은 가능(pb-text__body 동일 helper)하되 상속(기본값 레이어)은 pb 쓰기 경로가 full 객체(viewer-edit.js:3508-3546·marker 없음)라 sparse 전환 비용이 커 보류 — 현행 복사 버튼 유지. 무비=본문 textStyle 렌더 자체가 없어 대상 아님(제외 확정).

**마이그레이션**: 0을 달성. 기존 작품: textRuns 노드 부재 → helper가 즉시 현행 escHtml 경로로 폴백, 렌더 출력 byte-identical. 레거시 장면(marker 없음)·textDefaults 미보유 작품의 resolution 동작 무변경(resolver 무수정이므로). scenes 스키마·saveSceneText ALLOWED 무변경(runs가 scenes 밖). database.rules.json 무수정(viewer-meta 하위 상속) — 단 이 전제는 안전모드 사전감사 1건 필요: viewer-meta를 통째 set()하는 코드가 어디에도 없는지(saveViewerMeta 계열 전수 grep — 있으면 textRuns가 지워질 수 있어 별도 top-level 노드+rules 1항목 추가로 전환). 승격 상속 도입 시 유일한 체감 변화=기본값 첫 저장 순간 marker 없는 레거시 장면들이 일괄 따라오는 기존 REFINE-IA-2 특성인데, 이는 이미 라이브인 '이야기 전체' 탭과 동일 동작이라 신규 위험 아님(승격 칩 문구에 "다른 장면들도 함께 바뀌어요"를 명시해 의외성 제거). 롤백: textRuns 노드 무시 플래그 1개(또는 helper 폴백 강제)로 즉시 현행 복귀 — DB 정리 불요.

**위험**: 1) 오프셋 정합: _extractEditableText의 br/div 정규화와 렌더 span 구조가 어긋나면 무편집 저장에도 hash가 흔들려 강조가 소실 — 실패 방향이 '스타일만 사라짐'이라 본문은 안전하지만 학생 불만 소지, P1에서 추출↔오프셋 산출 규칙을 단일 함수로 공유해 차단+회귀 하니스 필수(단, 하니스 PASS≠실환경 — 실 viewer.html 확인 원칙 적용). 2) iPad/태블릿 드래그 선택 UX: 초등생이 contenteditable에서 롱프레스 선택 자체를 어려워할 수 있고 OS 선택 핸들·콜아웃 메뉴와 미니 툴바가 겹침 — 실기기 검증 전 성패 판단 불가(NOT_VERIFIED 최우선 항목), 대안으로 '문장 단위 탭 선택' 폴백을 P1 범위에 예비. 3) 타자기·runs 결합의 인덱스 버그(strip 재조립 시 run 경계 off-by-one). 4) 모둠 동시 편집: runs 노드 last-write-wins — 기존 장면 잠금 체계 안에서만 툴바 활성화로 완화. 5) 승격 칩의 값동등 marker 클리어가 '우연히 같은 값의 진짜 예외'까지 걷어낼 이론적 엣지(발생해도 값은 동일해 화면 무변화·marker만 소실). 6) 인쇄 미적용 기간(P1~P2)의 화면-인쇄 불일치 — 교사 인쇄 다수 경로라 P3 전 공지 문구 필요. 7) 과한 자유의 미감 붕괴 — 팔레트·2단 크기·상한으로 구조적 제한했으나 실수업 관측 1회 필요. 8) viewer-meta 통 set 존재 시 노드 위치 재결정(사전감사에서 판명).

**규모**: 신규 파일 0·functions 0·rules 0(감사 통과 전제). P1: viewer-data.js(runs 로드/검증/저장 ~120줄)+viewer-render.js(renderBodyWithRuns helper+텍스트 본문 삽입점 1곳+타자기 per-char ~130줄)+viewer-edit.js(selectionchange·오프셋 캡처/복원·미니 툴바·diff 이동 ~280줄)+viewer.css(~60줄)+viewer.html 캐시버스터 — 4파일 ~600줄. P2: viewer-edit.js 승격 칩+glyphapplyall 재구현 ~150줄. P3: viewer-render.js 엔딩 삽입점+picturebook-print.js helper 적용 ~80줄. P4(선택): pb 본문 runs 이식 ~60줄. 총 ~900줄 내외, 표준 모드(viewer 렌더/저장) + 사전감사·rules 판단만 안전모드. 하니스: runs validate/병합·오프셋 diff·helper 출력 동일성(runs 부재 시 byte-identical) 각각 focused로 가능.

**단계**: P0 사전감사(안전모드·반나절): viewer-meta 통 set 전수 grep→노드 위치 확정, iPad Safari contenteditable 선택+preventDefault 동작 PoC 1페이지(여기서 실패하면 '문장 탭 선택' UX로 선회 후 재설계 없이 진행 가능). P1 텍스트 모드 부분 강조(핵심 출시): runs 저장/검증+감상·다듬기 렌더+미니 툴바+타이핑 diff+타자기 — 감상은 runs 부재 시 현행과 byte 동일이므로 라이브 위험 최소, 실기기(iPad) 드래그 검증 후 배포. P2 상속 승격: '계속 쓰기' 칩+glyphapplyall의 textDefaults 방식 재구현+값동등 marker 클리어 — DB 쓰기 패턴은 기존 saveProjectTextDefaults 재사용이라 표준 모드. P3 일치성 마감: 인쇄 경로 helper 적용(실프린터 1회)+텍스트 엔딩 runs+export 포함 여부 결정. P4(관측 후 선택): 그림책 말풍선 runs 이식(상속은 이식 안 함), 무비 제외 확정. 각 단계 독립 롤백 가능(P1=플래그, P2=칩 숨김, P3=삽입점 원복)이며 한 단계씩 실수업 관측 후 다음 진행.

### 설계 3: 가둔 리치텍스트(LIMITED-RICH-1) — body 평문 정본 유지 + bodyRich 병행 오버레이 + 형광펜 툴바
**핵심**: body는 영원히 순수 문자열 정본(모든 기존 소비자 무변경). 부분 스타일은 다듬기 화면 전용 '형광펜'으로 제공하고, 제한 span 마크업(bodyRich)을 scenes 밖 별도 노드에 병행 저장한다. 렌더 시 strip(bodyRich)===scene.body일 때만 장식을 적용하고 불일치면 조용히 평문 폴백 — 이 자가 무효화 구조 덕에 body를 통째 교체하는 6개 편집 경로(maker textarea·미니모달·모바일·이야기길·AI 직접고침·contenteditable)가 코드 수정 0으로 자동 안전해진다. 부분 스타일은 절대값 금지: 크기 2단(big=1.25em/small=0.85em)+색 토큰 8종만 허용해 장면·작품 레벨 스타일/테마와 '곱'으로 합성되므로 상속(③)과 충돌하지 않는다. 정직한 판정: (a) body 안에 태그를 넣는 단일 필드 리치텍스트는 전면 기각 — escHtml 렌더 12곳(viewer-render.js:621 등)이 태그를 글자로 노출하고, textarea 4종이 원시 태그를 재저장 오염시키며, AI 프롬프트(prompts.js:625 verbatim)·safety 정규식·byte-hash 3종·글자수 4종이 전부 왜곡된다. (b) bodyRich 병행 오버레이는 '형광펜 수준으로 가두면' 초등 도구에 조건부 성립. 단 동일 UX를 오프셋 runs 직렬화(styleRuns)로 저장하면 sanitizer(신설 innerHTML 표면)가 아예 불필요해 더 안전 — 마크업 저장의 유일한 이점은 렌더 구현 단순성이므로, 본 설계의 편집·렌더 표면은 그대로 두고 저장 직렬화만 runs로 바꾸는 하이브리드를 우선 비교 검토할 것을 권고한다.

**데이터**: 위치: `{base}/textRich/{sceneNum} = { html, updatedAt, by }` — scenes 밖 별도 노드(aiVariants 패턴). scenes/{num} 자식으로 넣지 않는 이유: maker _flushPushToFirebaseNow(firebase.js:1102-1124)가 장면 노드 통째 write라 에코 전 클로버 위험. 화이트리스트: 태그는 `<span>` 단 1종·중첩 1레벨 금지, 속성은 data-fx∈{big,small}과 data-tone∈{t1..t8}만(기존 색칩 14종 viewer-edit.js:3013에서 가독성 좋은 8종을 토큰으로 매핑), style=/on*/기타 태그는 파서 기반 sanitizer로 전부 제거, 텍스트 노드는 escHtml. big/small은 em 상대·tone은 CSS 변수(v03-modes.css 토큰)로만 소비 — px/hex 직저장 금지(테마·상속과 충돌 0, 서버 allowlist 사상과 동일 철학). 유효성 검증: 렌더 시 _extractEditableText(viewer-edit.js:1642)와 동일 정규화를 거친 strip(html)===scene.body 비교(본문 ≤500자라 O(n) 무시 가능), 불일치=무시+lazy 삭제. rules: database.rules.json $team 하위에 와일드카드가 없음을 확인 — 신규 형제 노드는 rules 추가 필수. read=scenes와 동일 공개 게이트(isPublic∥active member∥교사), write=active member/담당교사로 처음부터 강화(신규 노드라 HARDEN-1 수준 선적용 가능, 기존 scenes write 완화 문제와 무관). 대안(rules 0 변경): scenes/{num}/textRich 자식 + saveSceneText ALLOWED(viewer-data.js:465-495) 등록 — 단 maker dirty-write가 위치이동 같은 비-본문 편집에도 장식을 지울 수 있어 차선.

**편집UX**: ②의 해법을 🎨 장면꾸미기 팝오버에 넣지 않고 별도 '플로팅 형광펜 툴바'로 분리한다(초등 인지 분리: 장면 전체=🎨, 고른 글자만=형광펜). 다듬기 contenteditable(data-pb-editable="body")에서 드래그 선택 시 selection 위에 미니 칩바(크게/작게·색칩 8·지우개) 출현 — selectionchange 리스너 신설(전례 0이나 글상자 핸들 오버레이 viewer-edit.js:1925+와 fixed 팝오버 viewer.css:640 전례 활용). 핵심 단순화: 툴바 컨트롤을 전부 button형으로만 구성(색=8칩 고정, 크기=2단 버튼 — select/range/color input을 의도적으로 배제)하고 전원 pointerdown preventDefault(전례 viewer-edit.js:1933) → blur 자체가 발생하지 않아 Range 저장/복원 인프라가 불필요해진다. 적용 시: 문자 오프셋으로 선택 캡처 → run 병합/정규화 → 본문 요소만 국소 innerHTML 교체(stage 통째 재렌더 금지, _patchTextStyle과 같은 급의 경량 경로) → 캐럿을 선택 끝으로 복원(전례 viewer-edit.js:1799-1804). 타이핑 중에는 DOM 무개입 — input마다 기존 _extractEditableText(평문, 무수정)+신설 _extractEditableRich(whitelisted span 워크→직렬화) 이중 추출만 수행해 커서 안전, 저장은 기존 300ms debounce에 편승. ④ 실수 복구: 지우개 칩(선택 부분 해제)+'강조 모두 지우기' 1탭(노드 삭제)+장면당 run 상한 약 6개(초과 시 "너무 많으면 읽기 힘들어요" 안내)로 과한 자유 차단. undo 스냅샷(state.js:110-121)은 body 기준이라 무영향. 다른 표면에서 본문이 바뀌어 장식이 소멸한 경우 다듬기 재진입 시 1회 토스트("본문이 바뀌어서 강조가 지워졌어요")로 버그 오인 방지.

**소비자**: AI(텍스트1/2·작품검사·나침반)=완전 무변경 — _buildWorkSnapshot(viewer-ai.js:3527)과 서버 프롬프트(prompts.js:625)가 body만 실으며 bodyRich는 스냅샷 밖. byte-hash 3종(작품검사 캐시 functions/index.js:186·s2 stale·race 비교 viewer-ai.js:4708)=body 기준 그대로 → 강조만 바꿔도 재검사·race 미발동(오버레이 분리의 결정적 이점). 글자수 4종·safety 정규식·LEN_RATIO=무변경. maker 카드 textarea·미니모달·모바일·이야기길=평문만 표시(태그 노출 0), 여기서 편집하면 strip 불일치로 장식 자동 소멸(정책: "본문을 고치면 부분 강조는 초기화"). AI 직접고침=revisedText 통째 교체 → 동일하게 자동 소멸(오프셋 재계산 불필요). 타자기(viewer-render.js:3101, textContent 분해)=1차엔 타자 완료 콜백 후 renderBody 재적용(강조가 타자 후 나타남), 길이 게이트 body 기준 무변경. 인쇄=1차 평문(화면-인쇄 불일치를 명시 공지) → P4에서 장면 인쇄·고쳐쓰기 자료에 동일 renderBody 헬퍼 이식(인쇄도 escHtml innerHTML 조립이라 이식 용이, print-color-adjust exact로 색 보존 확인). viewer 적재=adaptScenes(viewer-data.js:641) 미지 필드 폐기 관문을 회피 — scenes 밖 노드를 viewer-meta처럼 병렬 1회 read. export/import(ui.js:586)=scenes 밖이라 미포함 → 1차는 '내보내기엔 강조 미포함' 수용·문서화. 그림책 말풍선=2차 후보(pb-text__body도 escHtml 삽입이라 렌더 이식은 동일하나 좁은 폭+backdropOpacity 위 가독성 문제 — 텍스트 모드 실수업 관측 후 판단). 무비=본문 textStyle 렌더 자체가 없어 대상 외 확정.

**상속**: ③은 bodyRich와 직교 설계 — 부분 스타일이 상대 토큰(em·색토큰)이므로 base 스타일이 무엇이든 곱으로 합성된다. 이어짐 자체는 신규 체계를 만들지 않고 기존 resolver(viewer-data.js:1410-1447, marker 예외→작품 기본값→레거시 장면값→floor)를 활용한 '승격형'(전례조사 (c)): '이 장면만' 탭에서 스타일 저장 직후 팝오버에 "다음 장면들도 이렇게 할까요?" 승격 버튼 1개 추가 → saveProjectTextDefaults(viewer-data.js:514) 호출로 marker 없는 전 장면+새 장면+텍스트 엔딩이 동적으로 추종(resolver 무수정·DB 마이그레이션 0·신규 장면은 이미 textStyle 빈 값 생성이라 자동 편승). 한계를 정직하게: '모든 장면에 적용'을 이미 누른 작품은 전 장면 전 필드 marker라 승격이 안 먹음 → 승격 시 "예외로 지정된 장면도 덮을까요?" 선택지(=marker 일괄 해제, 기본 off)로 보완. weight는 textDefaults 범위 밖(viewer-data.js:1332)이므로 현행 유지(엔딩 bold floor 보존). 사용자가 말한 "장면2 마지막 설정이 장면3·엔딩에 이어짐"의 시간축 상속(생성 시 복사·이전 장면 체인)은 분기 DAG에서 '직전'이 모호하고 marker 딜레마·상류 수정의 하류 파급이 있어 채택하지 않음 — 승격 버튼이 같은 니즈를 명시적 1탭으로 흡수. 그림책 상속은 기본값 레이어 부재(saveProjectTextDefaults의 text 전용 가드 :515)로 본 트랙 범위 밖 — 렌더러가 이미 getTextStyle을 쓰므로 가드 해제+pb 기본값 노드 신설로 후속 확장 가능하나 별도 승인 트랙.

**마이그레이션**: 0. body 무변경, textRich는 신규 노드로 부재 시 지금과 byte-identical 렌더(기존 전 작품 그대로). 기존 textStyle/textStyleOverride/textDefaults/coverTheme 전부 무수정. 레거시 body-less 장면(title을 본문으로 해석 — state.js:114-120·viewer-data.js:633-636)은 형광펜 비노출 가드로 배제. 유일한 스키마 접점은 database.rules.json에 textRich 경로 read/write 추가 1건(안전 모드·배포 전 승인 대상) — scenes 자식 대안을 택하면 rules 0이지만 maker 클로버 감수. 롤백=클라 코드 원복만으로 완전(노드는 잔존해도 무시됨).

**위험**: (1) 최대 리스크: iPad Safari 한글 IME×contenteditable×span 경계 — 조합 중 span 분열·캐럿 점프 가능성(레포에 isComposing Enter 중복 버그 전례 있음). 완화=편집 중 DOM 무개입·적용은 버튼 시점만이지만, P0 실기기 스파이크에서 깨지면 이 각도 자체를 폐기해야 함. (2) sanitizer=지금까지 0이던 비-이스케이프 innerHTML 경로를 처음 여는 구조적 비용(학생 입력 XSS 표면). 파서 기반 whitelist·속성 enum 강제 필수 — runs 오프셋 직렬화로 바꾸면 이 표면이 소멸하므로, 마크업 저장을 고집할 근거는 렌더 단순성뿐임을 명시. (3) strip 비교 정규화 함정 — contenteditable의 br/div 정규화로 '무변경 저장'도 문자열이 미세하게 달라질 수 있어 반드시 _extractEditableText와 동일 정규화를 거쳐 비교, \n 처리 불일치 시 장식이 이유 없이 증발. (4) P4 전까지 화면-인쇄 불일치 — 인쇄 경로 다수 전제와 마찰, 교사 공지 필수. (5) 자가 무효화의 체감 비용 — 저학년이 "강조가 사라졌어요"를 버그로 인식할 수 있음(토스트·튜토리얼로 완화하되 완전 해소 불가). (6) 과한 자유의 부작용은 2크기·8색·run 상한으로 차단 — 자유 px/폰트/hex 개방은 절대 금지(가독성·작품 품질). (7) export 미포함·타자기 후행 적용 등 소소한 비대칭 다수(문서화 필요). 총평: '형광펜' 수준으로 가두면 초등 도구에 성립하나, 자유 리치텍스트로 확장하는 순간 무리 — 그 선을 지키는 것이 이 설계의 성립 조건.

**규모**: 클라이언트 5파일 중심, 신규 약 600~900줄: viewer-render.js(renderBody 헬퍼+본문 삽입 지점 ~6곳 치환+타자기 완료 훅), viewer-edit.js(플로팅 툴바·selectionchange·이중 추출 _extractEditableRich·캐럿 복원, ~300줄), viewer-data.js(textRich 적재/저장/strip 검증, ~120줄), v03-modes.css(fx/tone 토큰 ~40줄), viewer.html(툴바 컨테이너 1개). P4에서 picturebook-print.js 등 인쇄 이식 추가. functions 0·AI 프롬프트 0·기존 저장 경로 0 수정. rules 1경로 추가(안전 모드 승인). 검증=strip-일치 fuzz 하니스+sanitizer 악성 입력 세트+실기기 IME 필수(standalone 하니스 PASS≠실환경 원칙 적용, 최종은 실 viewer.html에서).

**단계**: P0 스파이크(선행 게이트): iPad Safari 한글 IME+span 편집+선택 유지 실기기 검증 1~2일 — 실패 시 각도 폐기하고 'runs 저장+뷰어 전용 렌더' 대안으로 회귀. P5(상속 승격 버튼)는 bodyRich와 완전 독립이라 P0와 병렬 또는 최우선 선출시 가능 — ③만 원하면 이것만으로 충족. P1: 데이터+렌더(textRich 노드·rules 추가·renderBody·strip 검증 — 표시만, 편집 없음, 기존 작품 렌더 byte-identical 회귀 확인). P2: 플로팅 형광펜 툴바(다듬기 전용·버튼만·pointerdown preventDefault·run 상한).
