# 생각 나침반 — PRD (대화형 의사결정 인터뷰 완료, 1·2·3차)

> 학생이 이야기를 만들기 **전에** 스스로 이야기 방향을 생각하도록 돕는 글쓰기 전 지원 기능.
> AI가 이야기를 대신 만들어주지 않는다. 이 문서는 PRD 인터뷰로 결정을 누적하는 살아있는 문서이며,
> 코드/Firebase/DB/UI 구현은 이 단계에서 다루지 않는다.

상태: **1·2·3차 인터뷰 전부 완료** — 운영정책(A–F, D-01~24) · 상세 질문/AI/화면(G~N, Q-01~21·AI-01~05·UX-01~17) · 데이터/와이어프레임/복구(O~Z, LOCK·STATE·DATA·WIRE·RECOVERY·TEACHER·RETENTION).
다음 단계(구현 아님): 코드·Firebase 적합성 read-only 감사 → 구현 Phase 로드맵 → 구현 전 테스트 계획.

---

## 1. 이미 확정된 핵심 원칙 (재질문 안 함)

### 1.1 강제 온보딩
- 신규 프로젝트 첫 진입 시 생각 나침반 강제 진행.
- 흐름: 새 프로젝트 생성 → 생각 나침반 강제 → 완료 → 제작 튜토리얼 → 튜토리얼 완료 → 자유 제작.
- 제공 안 함: 건너뛰기 · 나중에 하기 · 닫아서 우회 · 새로고침 우회.
- 도중 종료 시 저장된 단계부터 이어서 진행.

### 1.2 AI 역할
- 할 수 있음: 학생 답 확인 · 모호한 답 구체화 질문 · 필요 시 쉬운 보기 제공 · 앞뒤 모순 시 부드러운 이유 질문 · 참고용 요약 정리.
- 하면 안 됨: 장면 본문/행동버튼/장면 자동 생성·연결 · 결말/주인공/사건 대신 결정 · 작품 자동 완성 · 원본 덮어쓰기.

### 1.3 작품과의 분리 (참고용)
- 생각 나침반 결과는 참고용. 자동 수행 안 함: 장면 본문 입력 · 행동버튼 생성 · nextId 설정 · 시작 장면 지정 · 엔딩 지정 · 기존 작품 수정.

### 1.4 완료 후 위치
- 완료하면 다듬기 화면에서 언제든 다시 볼 수 있음.
- 쓰기 중에는 상시 AI 코치를 우선 구현하지 않고, 생각 나침반을 참고하는 기능부터 제공.

### 1.5 제작 튜토리얼 (완료 후)
- 행동 중심: ①준비된 표지·장면 확인 ②첫 장면 본문 ③행동버튼 개념 ④행동버튼 문구 ⑤다음 장면 연결 ⑥다듬기 진입 ⑦핵심 기능 안내 ⑧자유 제작 시작.

### 1.6 동시 접속 · 단일 편집권한
- 동시 접속 가능, **편집권한 1명 + 나머지 읽기 전용**.
- 읽기 전용 허용: 브랜치 보기 · 화면 이동 · 확대축소 · 카드 확인 · 연결 구조 확인 · 감상 열기.
- 읽기 전용 금지: 장면 추가·삭제·복사 · 카드 이동 · 본문/그림/행동버튼 수정 · 연결 생성·해제 · 장면 상태 변경 · 작품 설정 변경 · 생각 나침반 답변 · 튜토리얼 진행 · AI 적용 · 저장 작업 전부.
- 편집권한 요청 흐름: 읽기전용 요청 → 현재 편집자에게 표시 → 승인/거절 → 승인 시 pending 저장 후 권한 이전 → 기존 편집자 읽기전용. 자동으로 밀어내지 않음.

### 사용자가 추천과 다르게 선택한 항목
- **D-01**: 무비형 제외 (그림책·텍스트만).
- **D-04**: 도중 권한 이전 전면 금지 (한 편집자가 끝까지).
- **D-17**: 완성 결과를 브랜치+다듬기 양쪽에서 재열람 (MVP를 다듬기 전용으로 좁히지 않음).

### 잠재 충돌 / 후속 점검
- **D-04 vs D-21/D-22 (핵심 충돌)**: D-04는 "생각 나침반 완료 전 편집권한 이전 금지". 그러나 D-21(편집자 3분 무응답 → 이어받기)·D-22(권한 요청 30초)는 일반 편집 흐름의 이전 메커니즘. → 상세 설계에서 **"생각 나침반 진행 중" 모드에서는 D-21/D-22를 어떻게 제한할지** 명시 필요. 잠정 정리안: 정상 진행 중에는 요청/이어받기 모두 차단, 단 편집자 3분 만료(완전 이탈)일 때만 교사 확인 또는 이어받기를 예외 허용(모둠이 영구히 막히는 것 방지).
- D-17(브랜치+다듬기 재열람)은 1.4("다듬기 화면에서 다시 볼 수 있음")를 확장함 → 상세 설계에서 1.4를 D-17 기준으로 갱신. 브랜치 쪽은 작은 바로가기/요약 형태 범위 정의 필요.

# 2차 인터뷰 — 상세 질문/AI 판정/화면 설계 (완료)

> 운영정책(D-01~D-24)은 위에서 확정. 아래는 학생이 실제로 보는 질문·보기·AI 판정·결과 화면.
> 공통 원칙: 한 화면 한 질문 · 한 번에 한 가지 · 초등 표현 · 최대 두 문장 · 정답 느낌 금지 · AI가 답 대신 안 씀 · 보기는 방향만 · 직접 입력 동등 · 후속 질문 ≤2(전체 ≤5).

## 상세 질문 설계 (핵심 질문 7개)

### G1 — 예상 독자 (audience)
- **Q-01 문구**: "이 이야기를 가장 먼저 보여주고 싶은 사람은 누구인가요?"
- **Q-02 보기 3개**: 우리 반 친구들 / 가족 / 어린 동생이나 저학년 · 직접 입력 = "다른 사람을 직접 적을래요"
- **Q-03 충분 기준·후속**: 특정 사람 또는 비교적 분명한 집단이면 충분. 후속은 '모두·사람들·친구'처럼 **너무 넓을 때만 1개**: "그중에서도 가장 먼저 보여주고 싶은 사람은 누구인가요?" · 모르겠어요 = 공통 Phase I 흐름.

### G2 — 전하고 싶은 느낌·생각 (message)
- **Q-04 문구**: "이 이야기를 본 사람이 어떤 느낌이나 생각을 가졌으면 좋겠나요?" (느낌+생각을 한 질문에 함께)
- **Q-05 보기 3개**: 재미있고 긴장됐으면 좋겠어요 / 따뜻하거나 감동적이었으면 좋겠어요 / 어떤 문제를 한 번 더 생각했으면 좋겠어요(문제의식 보기 유지) · 직접 입력 = "내가 바라는 느낌을 직접 적을래요"
- **Q-06 충분 기준·후속**: 전하고 싶은 느낌/생각의 방향이 있으면 충분. 너무 넓을 때만 후속 1개: "어떤 부분에서 그런 느낌을 받았으면 좋겠나요?"(문제의식 선택 시 "어떤 문제를 생각하게 하고 싶나요?") · 모르겠어요 = 공통.

### G3 — 주인공 (protagonist)
- **Q-07 문구**: "누구의 이야기를 만들고 싶나요?" (사람 아닌 존재도 포함)
- **Q-08 보기 3개**: 사람 / 동물이나 생물 / 사물·로봇·상상 속 존재 · 직접 입력 = "직접 적을래요"
- **Q-09 충분 기준·후속**: 주인공 대상이 분명 + 특징 한 가지가 있으면 충분. 이름만 답하면 후속 1개: "그 주인공만의 특별한 점은 무엇인가요?" 또는 "그 주인공이 어려워하는 것이 있나요?" — **성격과 약점을 한 번에 함께 묻지 않음**. 모르겠어요 = 공통.

### G4 — 주인공의 목표 (goal)
- **Q-10 문구**: "주인공이 가장 이루고 싶은 것은 무엇인가요?" *(추천 B와 다른 선택)*
- **Q-11 보기 3개**: 중요한 사람이나 물건을 찾고 싶어요 / 누군가를 돕거나 지키고 싶어요 / 새로운 곳에 가거나 도전하고 싶어요 · 직접 입력 = "직접 적을래요"
- **Q-12 충분 기준·후속**: 원하는 행동·결과의 **대상이 분명**하면 충분. 보기만 고르고 대상이 비면 구체화 후속 1개: '찾기'→"무엇을 찾고 싶나요?" / '돕기'→"누구를 돕거나 지키고 싶나요?" / '도전'→"어떤 일에 도전하고 싶나요?". 직접 입력이 이미 구체적이면 생략. 모르겠어요 = 공통.

### G5 — 문제와 어려움 (obstacle)
- **Q-13 문구**: "주인공이 원하는 것을 이루기 어렵게 만드는 것은 무엇인가요?" (목표 G4와 연결)
- **Q-14 보기 3개**: 길이나 방법을 찾기 어려워요 / 누군가가 주인공을 방해해요 / 주인공의 두려움이나 약점이 방해해요(외부·사람·내면) · 직접 입력 = "직접 적을래요"
- **Q-15 충분 기준·후속**: 방해 요소가 하나라도 분명하면 충분. 너무 넓을 때만 후속 1개: "그 어려움은 왜 쉽게 해결되지 않나요?". **도움 주는 인물·해결 못 했을 때의 결과 위험은 여기서 묻지 않음**(과확장 방지). 모르겠어요 = 공통.

### G6 — 중요한 갈림길 (choice)
- **Q-16 문구**: "이야기에서 길이 갈라지는 중요한 선택은 무엇인가요?"
- **Q-17 보기 3개**: 혼자 해결할지 도움을 요청할지 / 안전한 길과 위험한 길 중 어디로 갈지 / 진실을 말할지 숨길지 · 직접 입력 = "직접 적을래요" · ⚠보기는 **방향 예시 수준**, 실제 작품의 행동버튼을 대신 만들지 않음. 선택 결과를 AI가 대신 작성하지 않음.
- **Q-18 충분 기준·후속**: 고민하는 **선택 순간 하나가 분명**하면 충분(두 갈래·결과 차이를 필수로 적게 하지 않음). 너무 넓을 때만 후속 1개: "두 선택을 하면 결과가 어떻게 달라질까요?". 모르겠어요 = 공통.

### G7 — 꼭 지키고 싶은 중심 (anchor) — AI 다듬기 보호 문맥과 직결
- **Q-19 문구**: "나중에 이야기를 고칠 때도 바꾸고 싶지 않은 것은 무엇인가요?"
- **Q-20 보기 3개**: 주인공의 성격이나 마음 / 꼭 넣고 싶은 장면이나 대사 / 결말의 의미나 이야기 분위기 · 직접 입력 = "직접 적을래요"
- **Q-21 충분 기준·후속**: 지키고 싶은 중심이 하나 분명하면 충분. 너무 넓을 때만 후속 1개: "그 부분을 꼭 지키고 싶은 이유가 있나요?"(이유까지 보호 문맥에 저장). 모르겠어요 = 공통.

### 후속 질문 전역 규칙
- 각 핵심 질문 후속 ≤ 2개. **세션 전체 후속 질문 ≤ 5개** (D-05 전체 최대 12개 한도와 연동). 7개 질문이 모두 후속을 유발해도 6번째부터는 후속 없이 NEXT로 통과시켜 상한 보장.

## AI 판정 규칙 (Phase J)
- **AI-01 decision** (J1): `NEXT` / `ASK_FOLLOW_UP` / `ASK_EASIER` 3개. 명백한 공백·반복 장난(D-13)은 **AI 이전 규칙 프리필터**로 처리(별도 decision 불필요).
- **AI-02 reasonCode** (J2): `SUFFICIENT` / `TOO_VAGUE` / `MISSING_DETAIL` / `CONTRADICTION` / `STUDENT_STUCK` / `OFF_TOPIC` 6개 전부.
- **AI-03 출력 규칙①** (J3): `acknowledgement`는 학생 답을 되짚으므로 **AI 생성**, 단 '완벽·최고·정답' 등 평가어 규칙 차단(D-11). `supportOptions`는 `ASK_FOLLOW_UP`·`ASK_EASIER`일 때만 제공, `NEXT`면 빈 배열.
- **AI-04 출력 규칙②** (J3): `followUpQuestion`은 한 문장 ≤ 40자. **JSON 파싱 실패·API 장애 시 decision=NEXT로 안전 통과**(진행 차단 금지, ack는 고정 문구) — D-15 fallback 정신과 일치.

### AI 출력 JSON (기준안)
```json
{
```

# 3차 인터뷰 — 데이터 구조 / 와이어프레임 / 실패·복구 (완료)

> 정본 Firebase 경로(조사): `classes/{classId}/teams/{teamEncoded}/scenes`. "프로젝트" = **팀 노드**. projectType='picturebook'|'text'. 기존 `viewer-locks.js`에 editorId·heartbeat·익명 uid 잠금 인프라 존재.

## 진행 중 편집권한과 잠금 복구 (Phase O)
- **LOCK-01** (O1): 생각 나침반 진행 중 일반 권한 이전은 금지(D-04). 단 편집자 **heartbeat 3분 없음 → 다른 학생이 "이 기기에서 이어서 진행할까요?" 확인 후 저장된 질문부터 재개**(교사 없이 복구). 고의적 이전은 여전히 차단.
- **LOCK-02** (O2): heartbeat는 **30초 주기 + 주요 저장·버튼 조작 시** 갱신.
- **LOCK-03** (O3): 이탈했던 이전 편집자가 복귀하면 **읽기 전용으로 전환**(새 편집자 유지, 자동 밀어내기 없음).
- **충돌 해소**: 위 1차 충돌 노트(D-04 ↔ D-21/D-22)는 LOCK-01~03으로 확정 — 진행 중엔 요청/이전 차단, 3분 완전 이탈만 학생 이어받기 예외.

## 데이터 저장 위치와 상태 구조 (Phase P)
- **DATA-01** (P1): 팀(작품) 노드 안 — `classes/{classId}/teams/{teamEncoded}/writingGuide/preWriting`. scenes 옆 형제 노드라 이동·복사·삭제·권한이 작품과 함께 움직임.
- **DATA-02** (P2): 입력 중 **debounce 임시 저장(draft) + '다음' 버튼에서 flush + 확정**.
- **DATA-03** (P2): debounce = **700ms**.
- **DATA-04** (P3): 답변은 `answerText` + `answerStatus`(`empty`/`draft`/`confirmed`) 한 값+상태로 임시/확정 구분.
- **STATE-01** (P4): 진행 위치를 **화면 단계까지** 저장 — `currentScreen`(`intro`/`coreQuestion`/`followUp`/`finalReview`/`summaryGenerating`/`completed`) + `currentCoreQuestionId` + `currentFollowUpIndex` + `totalFollowUpsUsed`. 새로고침 시 요약 생성·최종 확인 화면까지 정확히 복구.

## 질문·후속 답변 데이터 (Phase Q)
- **DATA-05** (Q1): 원답 보존 = **최신 답 + 직전 답 1개**(`answerText` + `previousAnswerText`). 잘못 수정 시 한 단계 복구.
- **DATA-06** (Q2): AI 후속 질문 저장 = **질문 문구·reasonCode·supportOptions·학생 답만**. 모델 정보·원본 AI 응답 전문은 미저장(개인정보·비용·복잡도↓).
- **DATA-07** (Q3): `acknowledgement`는 **저장하지 않음**(화면 반응용, 설계 데이터 아님).
- **DATA-08** (Q4): OFF_TOPIC 입력은 **횟수만**(`offTopicCount`) 저장. 장난 입력을 장기 로그로 남기지 않음.

## 최종 요약 데이터 (Phase R)
- **DATA-09** (R1): **원답 + 정돈 요약 모두 저장**(학생 원문 보호·비교 가능).
- **DATA-10** (R2): summary는 **7개 항목별 필드** — `audience`(G1)·`purpose`(G2)·`protagonist`(G3)·`goal`(G4)·`obstacle`(G5)·`branchChoice`(G6)·`protectedCore`(G7). (원답은 별도 `answers` 트리에 항목별 보존.)
- **DATA-11** (R3): AI 요약 실패 시 학생 결과 화면은 **정상과 동일**, **교사 상태 화면에만** fallback 여부 표시(`summaryMode: 'ai' | 'fallback'`).

## 신규·기존·복사 프로젝트 정책 (Phase S)
- **STATE-02** (S1): 강제 대상 = **`onboardingVersion` 필드 기준**. 신규 생성 시 `onboardingVersion:1` 부여 → 강제. 필드 없는 기존 작품은 강제하지 않음(사고 방지), 선택 실행만.
- **STATE-03** (S2): 기존 프로젝트는 **시작 전엔 선택, 한 번 시작하면 완료까지 강제**(신규와 동일, 미완성 방지).
- **STATE-04** (S3): 프로젝트 복사 시 **작품만 복사하고 생각 나침반은 초기화**(`onboardingVersion`/writingGuide 미승계). 교사용 템플릿엔 애초에 나침반 없음 → 학생 작품 복사·템플릿 복사 모두 결과는 "나침반 비어있음"으로 일관.

## 질문 화면 와이어프레임 (Phase T)
- **WIRE-01** (T1): **중앙 단일 카드** — 상단 진행률 / 중앙 질문 / 보기·입력 / 하단 이전·다음.
- **WIRE-02** (T3): **네 개 동등 카드 중 하나가 '직접 적기'**(D-07). 선택 시 입력창 펼침.
- **WIRE-03** (T2): 진행률 = **얇은 가로 막대 + 숫자**("생각 나침반 3 / 7"). 질문 화면 과장식 금지.
- **WIRE-04** (T4): AI 판정 대기 = **카드 하단 짧은 상태 표시**("생각을 살펴보고 있어요"). 전체 화면 막지 않되 중복 제출 차단.
- **WIRE-05** (T5): 이전 버튼은 **두 번째 질문부터 하단에 표시**.

## 읽기 전용 와이어프레임 (Phase U)
- **WIRE-06** (U1): 읽기 전용은 **현재 질문·선택지·입력이 모두 보이되 전부 disabled**(모둠 공동 의논 목적).
- **WIRE-07** (U2): 편집자 **입력 중인 글도 실시간 표시**(`draftText` 구독 — 기존 700ms draft write 재사용, 추가 write 거의 없음).
- **WIRE-08** (U3): 별도 pan/zoom 없음. **현재 질문 + 지금까지 확정된 짧은 요약** 열람 가능.

## 최종 확인·완료 화면 (Phase V)
- **WIRE-09** (V1): 최종 확인 = **세로 목록 7개**(태블릿·긴 답에 안전).
- **WIRE-10** (V2): 개별 수정 = **항목 클릭/작은 수정 버튼 → 해당 질문으로 이동 후 관련 후속만 재검토**(D-09).
- **WIRE-11** (V3): 요약 생성 중 = **짧은 전체 완료 전환 화면**("생각 나침반을 만들고 있어요"). **8초 타임아웃 초과 시 원답 fallback으로 즉시 완료**(강제 온보딩 차단 금지).
- **WIRE-12** (V4): 완료 결과 = **상단 작은 나침반 장식 + 7개 항목 전체 표시**(D-18 나침반 정체성 + 전체 가독성).

## 브랜치·다듬기 재열람 (Phase W)
- **WIRE-13** (W1): 브랜치 "🧭 생각 나침반" 버튼은 **구조 점검 근처**(이야기 방향 확인 기능끼리 묶음).
- **WIRE-14** (W2/W3): 브랜치·다듬기 모두 **오른쪽 overlay 서랍**으로 통일(브랜치=요약·캔버스 안 밀림, 다듬기=전체, 편집 흐름 비침범).
- **WIRE-15** (W4): 새 생각 메모는 **입력 중 debounce + 닫기 전 flush**(질문 답 저장과 동일 패턴).

## 실패·복구 시나리오 (Phase X)
- **RECOVERY-01** (X1): 네트워크 끊김 = 입력 허용 + **sessionStorage 로컬 임시보관**(프로젝트·질문별 키), 재연결 시 저장. '다음' 이동은 **저장 확인 후**.
- **RECOVERY-02** (X2): Firebase 저장 실패 = **자동 2회 재시도 + 수동 재시도**. 현재 답은 화면·sessionStorage에 유지.
- **RECOVERY-03** (X4): AI JSON 파싱 실패 = **동일 요청 1회 재시도 → 실패 시 NEXT 안전 통과**.
- **RECOVERY-04** (X3): AI 후속 질문 실패 = **1회 재시도 후 NEXT**(진행 차단 금지). 단 구체화가 중요한 **G3(주인공)·G4(목표)는 고정 후속 질문 fallback** 사용.
- **RECOVERY-05** (X5): 최종 요약 실패 fallback 후 **자동 재시도하지 않음**(완료 결과가 나중에 조용히 바뀌지 않음).
- **RECOVERY-06** (X6): 브라우저 종료 후 재접속 = **draft까지 복원** + 안내 "이어서 생각해볼까요? 적던 답을 불러왔어요."
- **RECOVERY-07** (X7): 같은 편집자 중복 탭 = **마지막으로 활성화된 한 탭만 편집, 다른 탭은 읽기 전용**.

## 교사 복구 기능 (Phase Y)
- **TEACHER-01** (Y1): 교사 상태 화면 = **상태·현재 질문·완료한 핵심 질문 수·마지막 저장 시각·현재 편집자·오류 여부**. heartbeat 상세값·fallback 사용 여부는 '고급 정보'로 접어둠.
- **TEACHER-02** (Y2): 초기화는 **전체 초기화만** 제공(부분 초기화는 정합성 위험).
- **TEACHER-03** (Y4): 교사 잠금 해제 = **현재 편집 세션만 해제 → 다음 접속자가 이어받음**(LOCK-01과 연결, 프로젝트 전체 잠금 해제 아님).
- **TEACHER-04** (Y3): 긴급 강제 완료 = **빈 항목을 '이야기를 만들면서 정할래요'로 채워 완료**. 강확인: "아직 답하지 않은 내용은 '이야기를 만들면서 정할래요'로 저장됩니다. 정말 생각 나침반을 완료할까요?"

## 데이터 보존·삭제 (Phase Z)
- **RETENTION-01** (Z1): 프로젝트 삭제 시 **생각 나침반도 함께 삭제**.
- **RETENTION-02** (Z3): 완료 후 원답은 **프로젝트가 존재하는 동안 보존**. 별도 대화 로그는 저장하지 않음.
- **RETENTION-03** (Z2): 학생 계정 삭제 시 나침반 **내용은 유지(모둠 공동 자산), 세션·작성자 식별 정보(익명 uid)만 제거/익명화**.
